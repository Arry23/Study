# 06 — S3

The most heavily examined storage service. You already have a well-configured
bucket in this workspace — [`arifa-infra/bootstrap/state.tf`](../arifa-infra/bootstrap/state.tf)
hits almost every control the exam cares about.

## The basics

- **Object storage**, not a filesystem. Flat namespace; "folders" are prefixes.
- Bucket names are **globally unique** across all AWS accounts.
- A bucket lives in **one region**; the name is global.
- Object size: 0 bytes to **5 TB**. Single PUT up to 5 GB; above that use
  **multipart upload**.
- **Strong read-after-write consistency** for all operations (since Dec 2020).

> **Trap.** Older material says S3 is eventually consistent. It is not —
> any question premised on eventual consistency in S3 is outdated.

## Storage classes

| Class | Use | Retrieval | Min duration |
|-------|-----|-----------|--------------|
| **Standard** | Frequent access | ms | — |
| **Intelligent-Tiering** | **Unknown/changing patterns** | ms | — |
| **Standard-IA** | Infrequent, needs ms access | ms | 30 days |
| **One Zone-IA** | Infrequent, **reproducible** | ms | 30 days |
| **Glacier Instant Retrieval** | Archive, needs ms access | ms | 90 days |
| **Glacier Flexible Retrieval** | Archive | 1 min – 12 h | 90 days |
| **Glacier Deep Archive** | Long-term, cheapest | **12 – 48 h** | 180 days |
| **Express One Zone** | Single-digit ms, very high TPS | ms | — |

Durability is **11 nines** for all classes. Availability differs; One Zone
classes store in a **single AZ** and are lost if that AZ is destroyed.

> **Exam tip — the three giveaways:**
> - "Access pattern is unknown or changes" → **Intelligent-Tiering**
> - "Can be recreated if lost" → **One Zone-IA**
> - "Compliance archive, retrieval in hours is fine, cheapest" →
>   **Glacier Deep Archive**

> **Trap.** Minimum storage durations mean moving small objects to IA or
> Glacier too early **costs more**. Lifecycle rules commonly use 30 days →
> IA, 90 days → Glacier.

## Lifecycle rules

```hcl
# arifa-infra/bootstrap/state.tf
resource "aws_s3_bucket_lifecycle_configuration" "state" {
  rule {
    id     = "expire-old-state-versions"
    status = "Enabled"
    filter {}

    noncurrent_version_expiration {
      noncurrent_days = 90
    }

    expiration {
      expired_object_delete_marker = true
    }

    abort_incomplete_multipart_upload {
      days_after_initiation = 7
    }
  }
}
```

Three actions worth knowing, all present above:

- **Transition** — move between classes after N days
- **Expiration** — delete current or noncurrent versions
- **Abort incomplete multipart uploads** — otherwise orphaned parts are
  **billed forever and invisible** in the console

> **Exam tip.** "Storage costs are higher than the object listing suggests" →
> incomplete multipart uploads, or old versions. Both are fixed with lifecycle
> rules.

## Versioning

Keeps every version of an object. Once enabled it can only be **suspended**,
never disabled.

- Deleting creates a **delete marker**; the data remains
- Deleting the delete marker restores the object
- You pay for **all** versions

> **Exam tip.** "Protect against accidental deletion or overwrite" →
> **versioning**. Combined with **MFA Delete** for the strongest protection.

In this workspace versioning is the stated recovery path for Terraform state:

```hcl
# Versioning is the recovery path: any earlier state can be restored.
```

## Object Lock

**WORM** — write once, read many. Requires versioning.

| Mode | Behaviour |
|------|-----------|
| **Governance** | Users with special permission can override |
| **Compliance** | **Nobody** can delete, including root, until retention expires |

Plus **legal hold** — indefinite, no retention period.

> **Exam tip.** "Regulatory requirement that records cannot be deleted for
> seven years, by anyone" → **Object Lock in Compliance mode**.

## Encryption

| Type | Key managed by | Notes |
|------|----------------|-------|
| **SSE-S3** | AWS | AES-256, default on all new objects |
| **SSE-KMS** | **AWS KMS** | Audit trail in CloudTrail, key policies, rotation |
| **DSSE-KMS** | KMS | Double encryption, for strict compliance |
| **SSE-C** | **You** | You send the key with each request; AWS never stores it |
| **Client-side** | You | Encrypted before upload |

All new objects are encrypted at rest by default (SSE-S3 minimum).

> **Exam tip.** "Need an audit trail of who decrypted what" or "control who can
> decrypt with a key policy" → **SSE-KMS**. "Must retain the keys ourselves and
> AWS must never hold them" → **SSE-C** or client-side.

> **Trap — KMS request quotas.** SSE-KMS calls KMS on every GET/PUT. High-TPS
> workloads can throttle. The fix is **S3 Bucket Keys**, which cut KMS calls
> by up to 99%.

This workspace uses SSE-S3 deliberately, documenting why rather than silently
accepting the weaker option:

```hcl
# SSE-S3 until the account's KMS key rules are known: a customer-managed key
# needs a key policy that says which roles may decrypt state.
#trivy:ignore:AVD-AWS-0132
```

### Encryption in transit

```hcl
statement {
  sid     = "DenyInsecureTransport"
  effect  = "Deny"
  actions = ["s3:*"]
  # condition: aws:SecureTransport = false
}
```

> **Exam tip.** "Enforce HTTPS for all bucket access" → a bucket policy denying
> when `aws:SecureTransport` is `false`. There is no checkbox for this.

## Access control

Five mechanisms, in order of preference:

| Mechanism | Use |
|-----------|-----|
| **IAM policies** | Principals in your account |
| **Bucket policies** | Cross-account, conditions, HTTPS enforcement |
| **Access Points** | Separate policies per application, one bucket |
| **ACLs** | **Legacy** — disable them |
| **Presigned URLs** | Temporary access for a specific object |

### Block Public Access

```hcl
resource "aws_s3_bucket_public_access_block" "state" {
  block_public_acls       = true
  block_public_policy     = true
  ignore_public_acls      = true
  restrict_public_buckets = true
}
```

On by default for new buckets, and account-level settings override bucket-level.

> **Exam tip.** "Ensure no bucket in the organization can ever be made public"
> → account-level Block Public Access, plus an **SCP**.

### Ownership controls

```hcl
rule { object_ownership = "BucketOwnerEnforced" }
```

`BucketOwnerEnforced` **disables ACLs entirely** and makes the bucket owner own
every object. This is the recommended modern setting, and it fixes the classic
cross-account problem where an uploader retained ownership.

### Presigned URLs

Time-limited URL carrying the creator's permissions.

> **Exam tip.** "Let a user download a private object without giving them AWS
> credentials" → **presigned URL**. Also used for direct browser uploads,
> keeping large files off your servers.

## Replication

| | CRR (cross-region) | SRR (same-region) |
|---|---|---|
| Use | DR, latency, compliance | Log aggregation, prod→test, account separation |

Requirements: **versioning on both** buckets, and an IAM role. Replication is
**asynchronous** and applies only to **new** objects unless you request
**batch replication** for existing ones.

> **Trap.** Replication is not transitive: A→B and B→C does not give A→C
> unless you enable replica modification sync.

**S3 Replication Time Control (RTC)** gives a 15-minute SLA.

## Performance

- Baseline: **3,500 PUT/COPY/POST/DELETE** and **5,500 GET/HEAD** per second
  **per prefix**
- Scale by using more prefixes
- **Multipart upload** for anything over ~100 MB; required over 5 GB
- **Transfer Acceleration** routes uploads via CloudFront edge locations
- **S3 Select** retrieves a subset of an object with SQL, reducing transfer

> **Exam tip.** "Users worldwide upload large files slowly" →
> **Transfer Acceleration** (or multipart upload). "Query a CSV in S3 without
> loading it all" → **S3 Select**, or **Athena** for multi-object SQL.

## Static website hosting

S3 can serve a static site, but only over **HTTP**.

> **Exam tip.** "Static site with HTTPS and a custom domain" →
> **S3 + CloudFront + ACM certificate**. S3 alone cannot do HTTPS on a custom
> domain.

Use **Origin Access Control (OAC)** so the bucket stays private and only
CloudFront can read it. OAC supersedes Origin Access Identity (OAI).

## Event notifications

S3 can notify on object creation, deletion, restore, replication:

```
S3 event → SNS | SQS | Lambda | EventBridge
```

> **Exam tip.** "Process each uploaded image" → S3 event → **Lambda**.
> "Many different consumers, filtering, archive to another account" →
> **EventBridge**.

## Other features worth knowing

| Feature | Purpose |
|---------|---------|
| **Storage Lens** | Organisation-wide usage and cost analytics |
| **Inventory** | Scheduled CSV/Parquet report of objects and metadata |
| **Batch Operations** | Act on billions of objects (copy, tag, restore, invoke Lambda) |
| **Requester Pays** | The downloader pays transfer costs |
| **Access Analyzer for S3** | Finds buckets shared externally |
| **Mountpoint for S3** | Mount a bucket as a filesystem |

## Exam decision table

| Requirement | Answer |
|-------------|--------|
| Unknown access patterns | **Intelligent-Tiering** |
| Reproducible data, cheap | **One Zone-IA** |
| 7-year compliance archive | **Glacier Deep Archive** + **Object Lock** |
| Cannot be deleted by anyone | Object Lock, **Compliance** mode |
| Protect against accidental delete | **Versioning** (+ MFA Delete) |
| Audit who decrypted | **SSE-KMS** |
| High TPS with KMS | **S3 Bucket Keys** |
| Force HTTPS | Bucket policy on `aws:SecureTransport` |
| Share one object temporarily | **Presigned URL** |
| Private bucket behind a CDN | **CloudFront + OAC** |
| DR copy in another region | **CRR** |
| Slow global uploads | **Transfer Acceleration** |
| SQL over one object | **S3 Select** |
| Find unexpected storage cost | Lifecycle: old versions, incomplete uploads |
| Prevent public buckets org-wide | Account **Block Public Access** + SCP |
